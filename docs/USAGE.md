## 快速开始

### 第一次使用

1. 访问您的 Hexo 博客管理器网址
2. 点击"使用 GitHub 登录"按钮
3. 在 GitHub 页面授权应用访问您的仓库
4. 授权成功后，在设置页面配置您的 Hexo 博客仓库
5. 开始创建和管理文章！

### 系统要求

- 现代浏览器（Chrome、Firefox、Safari、Edge）
- JavaScript 已启用
- 稳定的网络连接

## 登录和认证

### GitHub OAuth 登录

Hexo 博客管理器使用 GitHub OAuth 2.0 进行安全认证：

1. 点击登录按钮
2. 重定向到 GitHub 授权页面
3. 查看应用请求的权限：
   - **repo**: 访问您的仓库
   - **user**: 读取您的用户信息
4. 点击"Authorize"按钮授权
5. 授权成功后自动返回应用

### 会话管理

- 登录状态保存在浏览器 localStorage 中
- 会话有效期为 24 小时
- 超时后需要重新登录
- 可以在任何时间点击登出

## 配置仓库

### 设置仓库信息

1. 登录后，点击顶部导航的"设置"
2. 填写以下信息：
   - **仓库所有者**: GitHub 用户名或组织名
   - **仓库名称**: Hexo 博客仓库的名称
3. 点击"保存配置"按钮
4. 系统会验证仓库是否可访问

### 如何获取仓库信息

从您的 GitHub 仓库 URL 获取信息：

```
https://github.com/username/blog
         ↑         ↑
      所有者    仓库名
```

- `username` = 仓库所有者
- `blog` = 仓库名称

### 切换仓库

如需管理多个博客：

1. 在设置页面修改仓库信息
2. 保存后即可切换到新仓库
3. 文章列表会自动更新

## 创建文章

### 新建文章步骤

1. 点击"新建文章"按钮或导航到 `/new`
2. 输入文章标题
3. 在 Markdown 编辑器中编写内容
4. 实时预览渲染效果
5. 点击"创建文章"按钮保存到 GitHub

### 文件命名规则

新建文章时，系统会自动：

- 生成文件名：`title.md`（基于标题）
- 创建 front-matter：
  ```yaml
  ---
  title: 文章标题
  date: 2024-01-15 10:30:00
  ---
  ```
- 保存到 `_posts` 目录

### Markdown 语法示例

```markdown
# 一级标题

## 二级标题

### 三级标题

**粗体文本**
*斜体文本*
~~删除线~~

- 列表项 1
- 列表项 2

1. 编号列表 1
2. 编号列表 2

[链接文本](https://example.com)

![图片描述](image-url.jpg)

`行内代码`

```
代码块
```

> 引用文本

---

分割线
```

## 编辑文章

### 打开编辑器

1. 在文章列表中找到要编辑的文章
2. 点击编辑按钮（铅笔图标）
3. 编辑器会加载文章内容

### 编辑功能

- **实时编辑**: 所有更改即时保存到本地
- **预览切换**: 显示/隐藏预览面板
- **快捷键**: Ctrl/Cmd + S 保存
- **草稿恢复**: 自动检测未保存的草稿

### 保存更改

1. 修改文章内容
2. 点击"保存"按钮或按 Ctrl/Cmd + S
3. 系统会提交更改到 GitHub
4. 保存成功后显示确认消息

### 版本控制

每次保存都会在 GitHub 创建新的 commit：
- Commit 消息：`Update: 文章标题`
- 可以在 GitHub 查看完整历史
- 支持回滚到任意版本

## 删除文章

### 删除步骤

1. 在文章列表中找到要删除的文章
2. 点击删除按钮（垃圾桶图标）
3. 确认删除操作
4. 文章从 GitHub 仓库中移除

### 删除确认

删除操作需要二次确认：
- 显示文章标题
- 说明操作不可撤销
- 确认后立即执行

## 自动保存

### 自动保存机制

Hexo 博客管理器提供两级保存：

1. **本地自动保存**（自动触发）
   - 每 30 秒保存一次
   - 编辑器失去焦点时保存
   - 保存到浏览器 localStorage
   - 防止意外关闭导致数据丢失

2. **GitHub 提交**（手动触发）
   - 点击"保存"按钮
   - 按 Ctrl/Cmd + S 快捷键
   - 提交到 GitHub 仓库
   - 创建新的 commit

### 草稿恢复

下次打开编辑器时：

1. 系统检测是否有未保存的草稿
2. 显示恢复提示对话框
3. 选择"恢复草稿"或"放弃草稿"
4. 恢复后可以继续编辑

### 清除草稿

- 保存到 GitHub 后自动清除本地草稿
- 可以手动清除：清除浏览器 localStorage
- 每个文章有独立的草稿存储

## Markdown 编辑器

### 编辑器特性

基于 CodeMirror 6 的强大编辑器：

- **语法高亮**: Markdown 语法实时高亮
- **自动补全**: 常用语法快速输入
- **行号**: 显示行号便于定位
- **搜索替换**: Ctrl/Cmd + F 打开搜索
- **多光标**: Alt + 点击创建多光标

### 预览功能

实时 Markdown 渲染：

- **即时预览**: 编辑时实时更新
- **完整支持**: 支持 GitHub Flavored Markdown
- **样式一致**: 与 Hexo 渲染效果一致
- **响应式**: 适配各种屏幕尺寸

### 编辑器布局

- **分屏模式**: 左侧编辑，右侧预览
- **全屏模式**: 只显示编辑器或预览
- **移动适配**: 小屏幕自动切换为垂直布局

## 常见问题

### Q: 为什么需要 GitHub 账户？

A: Hexo 博客管理器直接与您的 GitHub 仓库交互，需要 OAuth 认证来安全地访问和管理您的博客文章。

### Q: 我的文章数据安全吗？

A: 是的，所有数据都存储在您自己的 GitHub 仓库中，我们不存储任何文章内容。会话信息加密存储在 Cloudflare KV 中。

### Q: 可以离线使用吗？

A: 可以，编辑器支持离线编辑。本地自动保存功能确保您的更改不会丢失，连接网络后可以提交到 GitHub。

### Q: 支持哪些 Markdown 语法？

A: 支持 GitHub Flavored Markdown (GFM)，包括：
- 标题、列表、引用
- 代码块、行内代码
- 链接、图片
- 表格、任务列表
- 删除线、自动链接

### Q: 如何插入图片？

A: 有几种方式：
1. 使用 Markdown 语法：`![描述](图片URL)`
2. 上传图片到 GitHub 仓库，然后引用
3. 使用外部图床服务

### Q: 可以编辑其他文件吗？

A: 当前版本专注于管理 `_posts` 目录下的 Markdown 文章文件。未来版本可能会支持更多文件类型。

### Q: 如何备份我的文章？

A: 您的文章都存储在 GitHub 仓库中：
1. 可以直接从 GitHub 下载
2. 使用 `git clone` 克隆整个仓库
3. GitHub 自动提供版本历史和备份

### Q: 支持团队协作吗？

A: 支持，因为使用 GitHub 作为后端：
- 多人可以同时编辑不同的文章
- Git 处理合并冲突
- 可以使用 Pull Request 审查更改

### Q: 移动端体验如何？

A: 专门为移动端优化：
- 响应式设计适配各种屏幕
- 触摸友好的交互
- 简化的移动端界面
- 支持移动端浏览器

### Q: 遇到问题怎么办？

A: 请尝试以下步骤：
1. 刷新页面
2. 清除浏览器缓存
3. 检查网络连接
4. 查看浏览器控制台错误
5. 联系技术支持
